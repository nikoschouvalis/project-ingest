# Accessibility Scan Instructions

## Category
- ID: `a11y`
- Name: Accessibility
- Finding Prefix: A11Y

## Purpose

Identify accessibility barriers in the frontend that prevent users with disabilities from effectively using the application. Focus on code-level patterns that indicate WCAG violations.

## Sub-Concerns

### 1. Semantic HTML
- Non-semantic elements used for interactive content (div/span as buttons)
- Missing landmark elements (nav, main, header, footer)
- Incorrect heading hierarchy (skipping levels, multiple h1s)
- Lists not using list elements (ul/ol/li)
- Tables used for layout (not data)
- Missing or incorrect use of ARIA roles

### 2. ARIA & Labels
- Interactive elements missing accessible labels
- Images missing alt text (or alt text that's not descriptive)
- Form inputs without associated labels
- ARIA attributes used incorrectly (aria-hidden on focusable elements)
- Redundant ARIA (aria-label on element that already has visible text)
- Missing aria-live regions for dynamic content updates

### 3. Keyboard Navigation
- Interactive elements not keyboard accessible
- Missing focus management on route changes / modal opens
- Focus traps (can't tab out of a component)
- No visible focus indicators (or focus indicators removed via CSS)
- Tab order that doesn't match visual order
- Custom components missing keyboard interaction patterns

### 4. Color & Visual
- Color as the only means of conveying information
- Insufficient color contrast (text on backgrounds)
- Missing dark mode / high contrast support
- Animations with no reduced-motion support
- Text in images without alternative

### 5. Dynamic Content
- Route changes not announced to screen readers
- Loading states not communicated accessibly
- Error messages not associated with form fields
- Toasts/notifications not in aria-live regions
- Modal/dialog focus management missing
- Infinite scroll with no accessible alternative

### 6. Media & Documents
- Videos without captions
- Audio without transcripts
- PDFs without accessible structure
- Missing skip navigation links
- Iframes without titles

## What to Look For

- Component files — semantic HTML usage
- Form components — label associations
- Interactive elements — button vs. div with onClick
- Image components — alt attributes
- Route/page components — heading structure
- Modal/dialog components — focus management
- CSS files — focus styles, color contrast, motion queries
- Navigation components — keyboard support

## What to Skip

- Third-party component library internals (flag if the library itself is inaccessible)
- Backend code (no a11y concerns)
- Exact color contrast ratios (tools measure this better)
- PDF accessibility (usually a content concern, not code)

## Applicability

This category only applies to frontend boundaries. If no frontend boundary exists, write a "Not Applicable" scan file.

## Context to Include

For each finding, note:
- The specific WCAG criterion violated (if identifiable)
- Which component/page is affected
- What user group is impacted (screen reader users, keyboard users, etc.)
- How widespread the pattern is
